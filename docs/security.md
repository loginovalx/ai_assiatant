# Границы доверия

MAX проверяет пользователя на входе в бот; Mini App API проверяет подписанный
`initData`. Модель не выбирает владельца: `user_id` скрыт из схем инструментов и
подставляется кодом. SQL ограничивает каждую операцию владельцем.

## Вызовы и подтверждения

- Модель видит и может вызвать только явный список календарных инструментов.
  Неизвестное имя отклоняется до обращения к MCP.
- Имена, описания, пользовательские сообщения и история считаются данными, которые
  не могут менять права или служебные параметры. Это указано в системном промпте.
- Через HTTP любое предложенное моделью изменение сначала выполняется с `dry_run`.
  Присланное клиентом `confirm_changes=false` защиту не отключает. Просмотр не требует
  подтверждения. Кнопки «Готово»/«На час позже» и действия Mini App — отдельные явные
  действия пользователя с проверкой владельца.
- Название операции, время и конфликты предпросмотра строит код по результату
  валидации, без повторной генерации моделью. Строки имён экранированы как JSON-строки.
- AgentService сохраняет текущий выданный черновик в Redis на 300 секунд, отдельно
  для каждого владельца. `/confirm` сверяет полное содержимое, включая ID, инструмент,
  аргументы и предпросмотр. При подтверждении новой операции выполняется только ранее
  выданный payload; произвольный `DraftAction` не даёт права записи.
- Проверка и выполнение сериализуются пользовательской Redis-блокировкой. Receipt
  успешного действия позволяет повторить HTTP без повторной записи. Создание также
  использует постоянный ключ идемпотентности в PostgreSQL.
- `edit_draft_id` разрешает восстановить исходную просьбу только из текущего
  выданного пользователю черновика. Модель не может подменить `user_text`.

## Внутренние сервисы

Agent API и MCP HTTP требуют разные сервисные bearer-токены. Они выводятся через
HMAC-SHA256 из одного приватного `LLM_API_KEY` с разными назначениями (`agent`, `mcp`).
Новых ручных токенов для настройки не требуется. Пустой ключ и `change-me...` закрывают
доступ. Ключ должен быть случайным и одинаковым в bot/agent/mcp; он не попадает в Mini App.
При ротации обновите все сервисы и прокси GigaChat вместе.

Это аутентификация доверенных сервисов, а не самостоятельная авторизация конечного
пользователя: сервис с ключом может действовать от имени пользователя. Не публикуйте
agent, MCP, Redis, PostgreSQL и gpt2giga; используйте закрытую сеть/localhost. При
межхостовом соединении нужен TLS/защищённый туннель. `/health` остаётся открытым.

## Проверки и пределы

Тесты моделируют скомпрометированные ответы модели: неизвестный инструмент, подмена
владельца, инструкции в календарном названии, изменение после чтения, маскировка
удаления в предпросмотре, изменённые/чужие/истёкшие черновики и повтор подтверждения.
Они проверяют ограничения кода, а не обещание модели следовать инструкции.

Защита не доказывает невозможность любой prompt injection: модель может предложить
неуместный черновик или текст, а пользователь может подтвердить его. Поэтому проверка
смысла перед кнопкой остаётся частью сценария. Компрометация серверного ключа, Redis
или самого бота выходит за границу защиты промпта и требует отдельного реагирования.
Не включайте отладочное логирование HTTP-тел с секретами или личными данными.
