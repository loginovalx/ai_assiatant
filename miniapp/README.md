# Мини-приложение MAX

Страница доступна на `/app/` HTTP API (порт 8000), отдельная сборка не нужна.
Есть периоды сегодня/завтра/неделя, фильтры, поиск, отметка выполнения и экспорт `.ics`.
Выполненные записи зачёркнуты; у записей без даты экспорт недоступен.

## Запуск

1. Заполнить `.env` по `.env.example`, включая `MAX_TOKEN`.
2. Запустить `docker compose up --build -d`. Миграции применятся автоматически.
3. Проксировать порт 8000 через HTTPS и указать `https://ваш-домен/app/` в настройках
   мини-приложения бота. У API и страницы один origin; менять адрес в HTML не требуется.
4. Открыть мини-приложение через MAX.

Для разработки в браузере включить `API_ALLOW_DEV_USER_ID=true` и открыть
`http://localhost:8000/app/?user_id=123`. В рабочем окружении оставить `false`.
На localhost адрес отдельного API можно указать через `?api=http://localhost:8000`.

## Авторизация и API

Страница загружает официальный MAX Bridge и отправляет `window.WebApp.initData`
в заголовке `X-Max-Init-Data`. API проверяет подпись HMAC-SHA256, уникальность полей
и срок действия (по умолчанию час), затем извлекает ID пользователя. Неподписанные
`initDataUnsafe` не используются для авторизации. Подмена `user_id` отклоняется.
Данные подписи не попадают в URL API и не сохраняются в localStorage.

- `GET /v1/me` — проверенный пользователь и часовой пояс.
- `GET /v1/events?from=...&to=...&include_undated=true` — список.
- `GET /v1/events/search?q=...` — поиск.
- `POST /v1/events/{id}/complete` — отметить выполненным.
- `GET /v1/events/{id}/ics` — экспорт; выполненная запись помечена в названии и без будильника.

Все запросы требуют заголовок авторизации, кроме явно включённого режима разработки.
Истёкшая подпись требует повторного открытия мини-приложения в MAX.

Документация MAX: [Bridge](https://dev.max.ru/docs/webapps/bridge),
[проверка подписи](https://dev.max.ru/docs/webapps/validation).
